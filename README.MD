# Финальный проект 4 модуля 

## 📌 Описание проблемы и её решение
В любом высоконагруженном приложении часто запрашиваемые и редко изменяемые данные (например, справочники стран, городов и языков) становятся узким местом при работе с реляционными базами данных. Постоянные тяжелые запросы с операциями `JOIN` нагружают процессор базы данных и замедляют ответы пользователю.

**Решение:** Вынести часто запрашиваемый набор данных в **Redis** — быстрое in-memory хранилище типа «ключ-значение».

## 🛠️ Стек технологий
* **Язык программирования:** Java 18+ (Amazon Corretto)
* **Сборщик проектов:** Maven
* **База данных:** MySQL 8.0
* **ORM-фреймворк:** Hibernate 5.6 (Jakarta Persistence API)
* **Кэш-сервер:** Redis 7.2
* **Драйвер Redis (Java):** Lettuce Core
* **Сериализация данных:** Jackson Databind
* **Логгер SQL-запросов:** P6Spy
* **Автоматизация инфраструктуры:** Docker, Docker Compose, Testcontainers

## 🚀 Запуск проекта в одну кнопку (Без ручной настройки)

Благодаря интеграции библиотеки **Testcontainers**, **НЕ нужно** вручную настраивать конфигурации запуска в IDEA или писать команды в терминале. Весь жизненный цикл Docker полностью автоматизирован внутри Java-кода.

### Шаг 1. Предварительные требования
Убедитесь, что на вашем компьютере установлен и запущен **Docker Desktop** (или Docker Daemon для Linux).

### Шаг 2. Запуск
1. Откройте проект в **IntelliJ IDEA Ultimate**.
2. Дождитесь, пока Maven скачает все необходимые зависимости (при первом открытии).
3. Откройте класс `ru.javarush.Main` (или ваш корневой класс с методом `main`).
4. Нажмите на стандартный зеленый треугольник **Run 'Main'** (Выполнить) в интерфейсе IDEA.

## ⚙️ Как это работает под капотом (Алгоритм работы)

Когда вы нажимаете кнопку **Run**, программа выполняет следующие шаги:

1. **Инициализация инфраструктуры:** Testcontainers перехватывает управление, находит файл `docker-compose.yml` в корне проекта и разворачивает контейнеры MySQL и Redis. При самом первом запуске образы скачиваются из Docker Hub автоматически.
2. **Развертывание дампа:** MySQL-контейнер автоматически подхватывает файл `dump-hibernate-final.sql` и разворачивает схему данных `world`.
3. **Ожидание портов (`Smart Waiting`):** Java-код приостанавливает выполнение до тех пор, пока контейнеры полностью не поднимут порты `3306` и `6379`, что полностью исключает ошибку `Connection refused`.
4. **Выгрузка из MySQL (Батчинг):** Через Hibernate и слой DAO приложение порциями по 500 записей вычитывает все города, минимизируя нагрузку на память.
5. **Трансформация (DTO):** Тяжелые сущности маппятся в легкий плоский объект `CityCountry`. Связи со странами и языками преобразуются в JSON-структуру.
6. **Кэширование:** Данные через Lettuce отправляются в Redis в формате `Ключ: ID города -> Значение: JSON строка`.
7. **Тестирование скорости:** Программа закрывает «прогретую» сессию Hibernate и делает серию поштучных запросов случайных ID к «холодному» MySQL и к Redis, замеряя время выполнения через `System.currentTimeMillis()`.
8. **Автоматическая очистка:** Блок `finally` гарантирует, что после вывода результатов в консоль, Testcontainers сам выполнит команду `docker compose down -v`, остановит контейнеры и очистит оперативную память компьютера.
